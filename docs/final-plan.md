## 1. 六个任务

| # | 任务 | 技能 | 成功判据 | 控制模式（动作维数） | 评估回合长度 |
| --- | --- | --- | --- | --- | --- |
| 1 | PickCube-v1 | 抓取 + 搬运到空中目标 | 方块距目标 ≤ 2.5 cm，**且**机械臂静止 | `pd_ee_delta_pos`（4） | 100 |
| 2 | StackCube-v1 | 抓取 + 精确放置（两阶段） | cubeA 落在 cubeB 上、已松开、静止 | `pd_ee_delta_pos`（4） | 200 |
| 3 | PushCube-v1 | 非抓取：从近侧往外**推** | 方块进入 goal_region | `pd_ee_delta_pos`（4） | 100 |
| 4 | PullCube-v1 | 非抓取：绕到方块远侧往回**拉** | 方块进入 goal_region | `pd_ee_delta_pos`（4） | 100 |
| 5 | PegInsertionSide-v1 | 抓取 + 紧公差侧向插入 | peg 头部进入孔中 | `pd_ee_delta_pose`（7） | 300 |
| 6 | PlugCharger-v1 | 抓取 + 位置和姿态对准的插接 | 距离 ≤ 5 mm **且**角度误差 ≤ 0.2 rad | `pd_ee_delta_pose`（7） | 200* |

- **控制模式和回合长度取自 ManiSkill 官方 DP 基线的 `baselines.sh`**：要转动末端的任务用 `pd_ee_delta_pose`。PullCube 没有官方值，按 PushCube 取；PlugCharger 也没有官方值，按 PegInsertionSide 取。
- **训练步数六个任务统一为 100k**（§3），取官方各任务中的最大值（PegInsertionSide），不再按任务区分。官方给 PickCube、PushCube、StackCube 的是 30k。
- *回合长度的规则：取 max(官方值, 示范平均长度 × 2)，再向上取整到 50 的倍数（「平均长度 × 2」是官方 README 的建议）。PlugCharger 的 200 是 ManiSkill 注册的默认值，采集完数据后按这条规则最终确定。
- **PullCube 不抓取方块**。ManiSkill 的专家求解器先闭合夹爪，把末端移到方块远侧，再往回拉。VariDP 教程把它写成「抓取 + 拖拽」，那是因为他们用的是自己写的脚本控制器；我们用官方求解器生成数据，所以报告里按「非抓取、与 PushCube 方向相反」来写。
- PlugCharger 还没试跑过，要先确认专家能生成、控制模式能转换（§2.3 关卡）。如果不通过，换成 LiftPegUpright-v1（已试跑通过，控制模式用 `pd_ee_delta_pose`）。

## 2. 数据

### 2.1 来源

示范全部由我们**自己运行 ManiSkill 官方运动规划求解器**生成（mplib 0.2.1 + 项目补丁），不下载官方数据集。求解器原生输出 `pd_joint_pos` 动作，然后用 `replay_trajectory` 转换成 `state` 观测和 §1 中的控制模式。采集、转换、评估一律使用 `physx_cpu` 后端（CPU 和 GPU 仿真在同一种子下的初始状态并不完全一致，不能混用）。

### 2.2 四个数据集与种子段

每个任务使用同一套种子编号：

| 用途 | 环境种子 | 规模 | 用在哪里 | 影响报告数字？ |
| --- | --- | --- | --- | --- |
| ① 训练示范池 | 从 0 开始顺序尝试，跳过规划或转换失败的种子，直到凑够 200 条 | 200 条 | **训练 loss 只在这里算**；前 N 条就是「N 条」的训练集 | 是（训练数据） |
| ② 验证示范 | 从 3000 开始顺序尝试，凑够 20 条 | 20 条 | 验证去噪 loss（噪声和时间步用固定种子），看是否过拟合 | 否 |
| ③ 验证 rollout | 5000–5049 | 50 回合 | 在训练进行到 1/3、2/3 和结束时各做一次闭环评估，画训练曲线 | 否，不用来挑检查点 |
| ④ 测试 rollout | 10000–10099 | 100 回合 | 对 `final.pt` 做唯一一次正式评估 | **报告数字全部来自这里** |

另外两类种子：

| 种子 | 取值 | 控制什么 |
| --- | --- | --- |
| 训练种子 | 1, 2, 3 | 网络初始化、batch 采样、训练时加的扩散噪声和时间步。**不改变用哪 N 条数据** |
| 推理采样种子 | 0（所有评估都用它） | 评估时 DDPM 采样的噪声 |

规则：

- 四段种子互不重叠（① 的上限是 2999）。训练脚本在启动时检查。
- **嵌套子集**：25 ⊂ 50 ⊂ 100 ⊂ 200，都取示范池的前 N 条。示范池的种子本身就是随机的初始状态，所以前 N 条等价于一个随机子集。换训练种子时不换子集。
- **专家参考上限**：在测试种子 ④ 上各跑一遍专家，记下专家的成功率，写进结果表作为参考。这些轨迹不用于训练。这样做的原因是：PegInsertionSide 的专家成功率只有约 1/3，训练池里天然缺少专家做不到的那些初始状态，而测试集里并没有把它们排除。

### 2.3 质量关卡（每个任务）

- 转换成功率：`pd_joint_pos` → 目标控制模式的转换。**事先规定：某个任务的转换成功率低于 90% 时，该任务改用 `pd_joint_pos`（8 维）**，并在报告里说明原因。
- 示范池全部 200 条在目标控制模式下重放成功，种子互不相同。
- 需要记录的统计量：专家成功率（成功条数 / 尝试的种子数）、轨迹长度（最短 / 中位 / 最长 / 平均）、动作范围、夹爪通道的分布（应当呈双峰），以及 SHA-256 清单。

## 4. 评估与统计口径

- **主指标** `success_once`（回合中任意时刻成功过），**次指标** `success_at_end`。每张表都注明用的是哪个指标。评估时忽略提前终止，每个回合都跑满回合长度。
- **每次训练**：测试集 100 回合，给出成功数 / 100 和 95% Wilson 区间。
- **每个格子**（3 个训练种子）：均值 ± 样本标准差，以及最小–最大值。pilot 中训练种子之间的标准差最大达到 0.20，远大于评估噪声（约 0.05），所以标准差必须报告。
- **两个格子之间的比较**：同一训练种子、同一测试种子配对，统计「只有 A 成功」和「只有 B 成功」的回合数；差值的 95% 区间用两层 bootstrap（先重抽训练种子，再重抽测试回合，共 10,000 次）。**区间不含 0 才说「有差异」，否则写「在这个样本量下分不出」**。如果要补训练种子 4、5，就给这组比较的所有格子一起补。
- **失败分类**：成功并保持到结束 / 成功后又失去 / 从未成功。PegInsertionSide 和 PlugCharger 再按阶段细分为：没抓到、抓偏、没对准、插到一半卡住（抽样看视频，每类至少看 5 个回合）。
- **效率指标**：参数量、训练每步耗时、峰值显存、每次推理耗时。轨道 B 必须报告，其余部分顺带记录。同一张表里的耗时必须来自同一型号的 GPU。

## 5. 轨道 A：数据量

| 项目 | 取值 |
| --- | --- |
| 自变量 | N ∈ {25, 50, 100, 200}，取示范池的前 N 条 |
| 主干 | UNet（B0） |
| 训练步数 | 100k（§3），**与 N、任务都无关**：N 越小，每条数据被重复看的次数越多，这正是「数据少」的真实情况。报告里写明口径是「固定步数」而不是「固定 epoch」 |

1. 六个任务的「成功率–log₂N」曲线，误差线表示训练种子之间的标准差；
2. 相邻两档之差及其 bootstrap 区间，标出从哪一档起「分不出提升」；
3. 每个任务「达到 N=200 成功率的 80% 需要多少条」，用插值估计；
4. 失败类型怎样随 N 变化。

## 6. 轨道 B：模型结构

**只换去噪网络** ε_θ(a_t, t, obs)。三种主干的输入完全一样：加噪后的动作块（16 × 动作维数）、扩散时间步，以及归一化后的两帧观测拼成的向量。数据（N=100）、归一化、horizon、DDPM、优化器、步数、EMA、评估，全部与 §3、§4 相同。

| 编号 | 主干 | 结构参数 | 观测怎么注入 | 参数量（实测：4 维动作、42 维观测；7 维动作时差别在 0.1M 以内） | 来源 |
| --- | --- | --- | --- | --- | --- |
| **B0** | 1D 卷积 UNet | down_dims [64, 128, 256]，kernel 5，GroupNorm 8 组，时间嵌入 64 维 | FiLM（每个残差块） | 4.4M | ManiSkill 官方基线 `conditional_unet1d.py`，与原版 DP 相同 |
| **B1** | Transformer | d_model 256，4 层，4 头，FFN 1024，pre-LN，因果 mask | 观测和时间步各作为一个前缀 token | 3.2M | VariDP `backbones.py::DiffusionTransformer` |
| **B2** | MLP | 隐藏层宽 1024，4 层，Mish + LayerNorm，时间嵌入 128 维 | 与动作块、时间嵌入直接拼接 | 3.5M | VariDP `backbones.py::MLPNoisePred`，加宽 |

规则：

- **参数量对齐到同一量级（3–5M）**。VariDP 的 MLP 默认（256 宽、3 层）只有约 0.2M（不含它的观测编码器），不到 UNet 的 1/20，用它比较的话「结构」和「容量」混在一起分不开，所以把 MLP 加宽到 3.5M。B0 用官方 UNet，不用 VariDP 自己写的 UNet（2.8M），因为 B0 同时也是六任务基线，要能说明它就是官方实现。
- **不针对单个主干调参**：三种主干共用 §3 的优化器设置。唯一的例外是某个主干在验证集上明显不收敛：这时只允许在验证 rollout ③ 上为它试 3 个学习率（3e-4 / 1e-4 / 5e-5），选定后在报告里写明。
- 格子：6 任务 × 3 主干 × 3 个种子 = 54 次，其中 B0 的 18 次与基线共用。

产出：

1. 主干 × 任务的成功率表（均值 ± 标准差），附与 B0 的配对差值区间；
2. 效率表：参数量、训练每步耗时、峰值显存、每次推理耗时；
3. 「成功率–推理耗时」散点图；
4. 验证去噪 loss 曲线，三种主干画在同一张图上（同一任务内三者可以直接比较，因为数据和归一化完全相同）。

## 8. 与 VariDP 教程的对照

| 项目 | VariDP 教程 | 本计划 | 理由 |
| --- | --- | --- | --- |
| 示范来源 | 下载官方数据后转换；另用自写脚本控制器生成 2–3 个任务 | 自己运行官方运动规划器，六个任务全部自己生成 | 课程明确规定只下载数据不算完成；我们的 Linux 机器上 mplib 可用 |
| 控制模式 | `pd_ee_delta_pos`；Peg、Plug 用 `pd_ee_delta_pose` | **采纳** | 与官方基线一致，可以和官方结果对照 |
| 回合长度 | 按 `baselines.sh` | **采纳** | 同上 |
| 训练步数 | 按 `baselines.sh`（30k / 100k）；他的实测里 batch 256 × 30k 步明显训练不足 | 六个任务统一 100k，batch 1024 | 取最大值统一，简单任务也不会训练不足；任务之间可以直接比较 |
| 训练 / 测试种子 | 训练用 0…n−1，测试用 2000–2049（50 回合） | 训练池从 0 起，验证用 3000+ 和 5000–5049，**测试用 10000–10099（100 回合）** | 测试回合多一倍，评估噪声更小；验证与测试分开。**全组要统一用一套种子** |
| 验证集 | 从同一批示范里随机划出 10%，划分随训练种子和 `demo_frac` 变化 | 固定的 20 条独立验证示范 | 保证所有 N、所有主干用的是同一个验证集，loss 才能互相比较 |
| 挑选检查点 | 取验证 loss 最低的 `best.pt` | 固定用 `final.pt` | pilot 中按验证挑出的检查点在测试集上更差；去噪 loss 和成功率的相关性本来就弱 |
| 归一化统计量 | 在全部示范（含验证集）上计算 | **只在训练的 N 条上计算** | 教程 §6.4 自己也要求这样做，但 `train_dp.py` 里 `stats=full.stats` 用的是全部数据 |
| 数据量实验 | `demo_frac` 按比例抽随机子集，每个种子抽到的子集不同 | 绝对条数 25/50/100/200，嵌套，不随种子变化 | 种子间的方差只反映训练随机性；条数也不随示范池的大小而变 |
| 推理 | DDIM 10 步 | DDPM 100 步 | 与官方基线一致。采样步数本身可以作为轨道 B 的附加测量（同一个检查点换采样步数），但不作为主结果 |
| batch / EMA | 256 / 0.995 | 1024 / 官方 EMA | 与官方基线一致 |
| 主干 | MLP / 自写 UNet / Transformer | 官方 UNet / VariDP Transformer / 加宽的 VariDP MLP | 见 §6 |
| 训练种子 | 关键结论至少 3 个 | 所有格子都是 3 个 | 一致 |

## 9. 已确认的决定（9.24）

1. **控制模式改用 ee-delta**：PickCube、StackCube、PushCube、PullCube 用 `pd_ee_delta_pos`，PegInsertionSide、PlugCharger 用 `pd_ee_delta_pose`。这与 pilot 用的 `pd_joint_pos` 不同；某个任务的转换成功率低于 90% 时退回 `pd_joint_pos`（§2.3）。
2. **MLP 加宽到 3.5M**，与 UNet、Transformer 的参数量在同一量级；不另外跑 VariDP 原来的小 MLP。
3. **全组统一种子和检查点口径**：测试种子 10000–10099（100 回合），报告只用 `final.pt`；VariDP 那边相应修改。
4. **训练步数六个任务统一为 100k**（原先按官方值，四个任务是 30k）。代价是这四个任务的训练时间变为约 3.3 倍；N=25 时每条示范要被看过上万遍，可能过拟合。要在训练到 1/3、2/3 和结束时的验证 rollout 上检查成功率有没有后期下降，如果有，就在报告里如实写明，不改变口径。
